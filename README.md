## 已执行的检索分析

基线执行命令：`python evaluate.py --output experiments/keyword_only.json`。随后由用户完成模型下载，并执行 `python evaluate.py --index data/movie_index.npz --index data/multilingual.npz`，对比结果见 `retrieval_results.json`。

语料：7 部电影；25 条人工构造的库内查询、5 条样例片库外查询。查询与标注在 `data/eval_queries.json`，完整排序记录在 `keyword_only.json`。

| 系统 | MRR@5 | Recall@5 | 无关查询错误接受率 | 正例空结果率 |
| --- | --- | --- | --- | --- |
| 标题／属性匹配基线 | 0.720 | 0.760 | 0 / 5 | 6 / 25 |
| all-MiniLM-L6-v2 | 0.840 | 0.973 | 5 / 5 | 2 / 25 |
| paraphrase-multilingual-MiniLM-L12-v2 | 0.848 | 0.947 | 3 / 5 | 2 / 25 |

多语言模型在本组样例上的首位排序指标略高，阈值 0.45 下的错误接受较少，但 Recall@5 略低；样本太少，暂保留原模型作为默认值。两者仍会对无关输入返回电影。MRR 和 Recall 使用未按阈值截断的排序，不能与拒识指标混为一谈。

计时数值保留在 JSON 中，仅为该环境中的单次功能分析，不作为性能承诺。

两个值得保留的失败案例：

- `plot-1`：“带着地球逃离即将毁灭的太阳”。虽然与《流浪地球》简介含义相近，整句没有作为子串出现，标题／属性基线不能理解这种改写，返回空结果。
- `compound-1`：“姜文导演的动作片”。基线采用属性命中的并集，没有理解“导演和类型必须同时满足”，会把《让子弹飞》放在《邪不压正》前面。显式选择“动作”类型可以缩小结果，但不等于已经实现自然语言条件解析。

这些查询来自同一份样例元数据，未独立标注，不能作为独立测试集。片库只有 7 条，Top-5 很宽松；不使用这些指标宣传真实用户收益。
